# XML → CODESYS 部署手册

适用分支：`lx` ｜ 交付内容：把 PLCopen XML（IEC 61131-10）自动部署到 CODESYS 软 PLC 运行，
并用 UaExpert 通过 OPC UA 观察「每秒自增 1」的计数器变量。

---

## 0. 链路总览

```
src/plc/counter.xml ──► run_deploy.py ──► CODESYS.exe --noUI --runscript
                                              │
                                   deploy_project.py（CODESYS 内部）
                                   ①建/开工程 ②加设备 ③导入XML替换PLC_PRG
                                   ④符号配置(OPC UA发布) ⑤编译 ⑥下载+运行
                                              │
                              workspace/deploy_result.json（步骤成败+错误）
                                              │
                        CODESYS Control Win V3 ── OPC UA ──► UaExpert 观察 cnt
```

## 1. 软件安装（一次性，约 30 分钟）

### 1.1 CODESYS Development System + 软 PLC

1. 到 https://www.codesys.com 注册免费账号（需邮箱验证）
2. 登录后进入 **CODESYS Store**，下载 **CODESYS Development System V3.5**（选最新 SP，64 位安装包，如 "CODESYS 3.5 SP19 Setup (x64)"）
3. 运行安装程序，组件勾选：
   - ✅ **CODESYS Development System**（含 Scripting 组件，默认勾选）
   - ✅ **CODESYS Control Win V3 x64**（本机软 PLC —— 必勾）
4. 默认安装到 `C:\Program Files\CODESYS 3.5.SP19.0\CODESYS\CODESYS.exe`，
   编排器会自动扫描该位置；装到别处请设置环境变量：
   `set CODESYS_EXE=C:\<你的路径>\CODESYS.exe`

### 1.2 Python

本机已装 3.12 ✅（流水线只用标准库；`pip install -r requirements.txt` 装 pytest 即可跑单测）。

### 1.3 UaExpert（OPC UA 客户端）

到 https://www.unified-automation.com/products/development-tools/uaexpert.html
免费注册下载安装。

## 2. 一次性环境准备

1. **启动软 PLC**：开始菜单运行 `CODESYS Control Win V3 SysTray`（或 Win V3 x64），
   系统托盘出现图标即运行中。
   - 首次启动弹出的 **Demo 模式**提示选接受：无许可证时全部功能可用，
     **每 2 小时自动停一次**，从托盘重新 Start 即可（属正常现象）。
2. **防火墙**：首次启动 Windows 会询问放行，勾选专用+公用网络；
   或手动放行 TCP **1217**（CODESYS 网关）与 **4840**（OPC UA）。
3. 自检：CODESYS IDE → Tools → Connect to device…，能在列表里看到本地 runtime 即就绪。

### 2.3 第一次操作：一次性工程播种（保姆级步骤，约 5 分钟，仅此一次）

> **为什么需要这一步**：SP22 的无头脚本接口无法自动写入网关绑定和符号配置
> （`online.gateways` 在 `--noUI` 下为空；`create_symbol_config` 所有调用形态均被拒，
> 已实测穷举）。但这两样东西**保存在工程文件里**，在 IDE 里点一次，之后所有自动
> 部署（含 `POST /deploy`）永久复用，换工程也有模板机制接管（见 §6.1）。

**开始前 1 分钟自查**

- 软 PLC 在运行：任务栏右下角有 CODESYS 托盘图标；或命令行
  `sc query "CODESYS Control Win V3 - x64"` 显示 `STATE: RUNNING`
  （本机此前已通过管理员启动，一般无需再管）
- 如果 IDE 里已开着别的工程，先关掉（文件 → 关闭工程）

**第 1 步：打开工程（约 30 秒）**

1. 在资源管理器中**双击** `D:\Study\SIMENS PLC\workspace\counter.project`
   （等价方式：开始菜单 CODESYS → 文件 → 打开工程 → 选该文件）
2. 加载约 10~30 秒。若弹出安全/版本提示对话框，点「确定 / 是」
3. 成功标志：左侧「**设备**」窗格出现这棵树——

```
counter
 └─ CODESYS Control Win V3 (CODESYS Control Win V3)
     └─ Application
         ├─ PLC_PRG
         ├─ 任务配置
         └─ 库管理器
```

   看不到设备窗格：菜单「视图 → 设备」调出来。

**第 2 步：配置通信网关（约 1 分钟）**

1. 设备树中**双击设备节点** `CODESYS Control Win V3 (CODESYS Control Win V3)`
   ——注意是**设备本身**（树的第一层子节点），不是 Application
2. 窗口中间出现设备编辑器，顶部有一排选项卡，点「**通信设置**」
3. 找到「**网关**」下拉框：
   - 列表里已有 `CODESYS Gateway 3.5.22.30 <本机IP>` → 直接选中它
   - 列表为空 → 点旁边的「**添加网关**」→ 名称随意（如 `local`）、主机名填
     `localhost` → 确定 → 选中刚加的这条
4. 找到「**设备名称 / 地址**」区域 → 点「**扫描网络...**」按钮
   → 在扫描结果里选中 `CODESYS Control Win V3`（地址 127.0.0.1.1.1）→ 确定
5. **成功标志：设备名旁出现绿点**，通信面板显示 runtime 版本信息
   - 若弹「固件/版本不同，是否继续」→ 选「是」
   - 若弹登录框 → 默认用户直接确定

**第 3 步：添加符号配置 = OPC UA 发布开关（约 1 分钟）**

> SP18+ 里这个对象可能叫「**符号配置**」（传统名）或「**符号集配置 / IEC 符号集**」
> （新名），随安装的组件版本而定。**找不到就先做这一步**：
> 在「添加对象」对话框**顶部的搜索框**里输入 `符号`（或 `symbol`），列表会过滤出
> 相关对象，有哪个就用哪个，操作见下方 A/B 两条路线。

**路线 A：找到「符号配置」（传统对象）**

1. 设备树中**右键 `Application`** → 「**添加对象**」→ 「**符号配置...**」
2. 对话框里**勾选「支持 OPC UA 特性」**（Support OPC UA features）→ 点「**添加**」
3. Application 下出现「符号配置」节点 → **双击打开它**
4. 编辑器左上点「**准备...**」按钮 → 变量树刷出来（能看到 `PLC_PRG` → `cnt`、`pulse`）
5. 勾选 `PLC_PRG` 整个节点（父节点勾上，子变量跟着勾）
6. **最关键的一下**：勾选「**总是更新变量**」复选框（编辑器顶部/准备按钮附近）
   ——勾了它，以后每次部署新程序，新变量自动进符号表并发布，不用再开这个编辑器

**路线 B：只有「符号集配置 / IEC 符号集」（SP18+ 新对象）**

1. 右键 `Application` → 「添加对象」→ 「**符号集配置**」（或 IEC 符号集配置）
2. 打开后**新建一个符号集**（名字随意，如 `plc_io`）
3. 在符号集里添加要发布的对象：选 `PLC_PRG`（其变量会整体纳入）
4. 保存（新机制是预编译符号处理，无需"准备"按钮，也没有"总是更新"——
   符号集按对象引用，换程序后重部署即自动刷新）

**两条路线收尾相同**：关闭编辑器 → **Ctrl+S 保存工程** → IDE 可以整个关掉

**第 3.5 步：放行匿名 OPC UA 访问（runtime 安全策略，必做）**

不放开这个，UaExpert 会连上但读不到变量：

1. 设备树**双击设备节点**（和第 2 步一样进设备编辑器）
2. 菜单「**设备 → 更改运行时安全策略...**」（Change Runtime Security Policy）
3. 「**设备用户管理**」下拉选「**可选的用户管理**」，并**勾选「允许匿名登录**」
4. 点「**访问权限**」→「**同步**」→ 展开「**RemoteConnections**」→ 选 `OPCUAServer`
   → 对 `Anonymous_OPCUAServer` 勾选「**修改、查看和执行**」
5. 一路确定

**第 4 步：验证播种（回到命令行）**

确保 IDE 已关闭该工程（文件锁冲突会导致失败），然后：

```bash
python src\pipeline\run_deploy.py
```

期望输出：所有步骤 `[PASS]`，结尾 `RESULT: OK` 和
`[orchestrator] 部署成功，PLC 已在运行。`

**第 5 步：UaExpert 看到每秒 +1（最终验收）**

1. 打开 UaExpert → 工具栏「**+**」→ Server URL 填 `opc.tcp://localhost:4840`
   → Security Settings 保持 `None` → OK
2. 双击刚建的连接 → 首次弹出服务器证书对话框 → **Trust / 接受**
3. 左侧 Address Space 逐层展开 `Objects → 设备/应用节点 → PLC_PRG`，
   或直接在过滤框输入 `cnt` 搜索
4. 把 **`cnt`** 拖进右侧 **Data View** → **数值每秒 +1 = 全链路打通 ✅**
   （`cnt` 是 DINT 从 0 起跳，脉冲由 `T#1S` 的 TON 产生）

**卡住了？**

| 现象 | 处理 |
|---|---|
| 双击 .project 没有关联程序 | 右键 → 打开方式 → 选择 CODESYS |
| 添加对象里找不到符号配置 | 用对话框顶部搜索框输 `符号`；出现的是「符号集配置」就走路线 B；两者都没有 → 缺组件：工具 → CODESYS 安装程序，勾装 CODESYS Communication 相关组件 |
| 扫描网络找不到设备 | runtime 没跑：见 §2.1 启动；防火墙放行 1217 |
| 通信灯不绿 | 网关选错/没加：重复第 2 步 3~4 小步 |
| 部署时报工程被占用 | IDE 还开着工程：关闭后重跑 |
| UaExpert 能连接但看不到变量 | 没做第 3.5 步（匿名 OPC UA 放行），或符号配置没勾到 `PLC_PRG` |
| UaExpert 连不上 4840 | `telnet localhost 4840` 不通则 runtime 停了，重启后重新部署；另检查 Windows 服务「OPC UA Local Discovery Server」是否占用 4840，占用则停用并设为手动 |

实在点不动就把**当前界面截图**发到群里/助手，标一下卡在第几步。

> **播种完成后**：告知助手（或自己在仓库根目录执行
> `copy workspace\counter.project src\codesys\template.project`），
> 模板入库后，今后本机/新机器/新工程全部自动从模板生成，不再有任何 GUI 步骤。

```

期望输出（每步 PASS，最后 `RESULT: OK`）：

```

[PASS] create project

## 4. UaExpert 验证（看到每秒 +1）

1. 打开 UaExpert → 左上 **"+"** → Server URL 填 `opc.tcp://localhost:4840`
2. Security Settings 保持 **None** → **OK** → 双击新连接
3. 首次连接弹出证书信任对话框 → **Trust/Accept** 服务器证书
4. 左侧 **Address Space** 逐层展开：`Objects → <PLC 设备名> → Application → PLC_PRG`
   （不同 SP 版本节点层级略有差异，可直接在过滤框输入 `cnt` 搜索）
5. 把 **`cnt`** 拖入右侧 **Data View**
6. 观察数值：**每秒 +1** 即链路全部打通 🎉
   （`cnt` 为 DINT，从 0 起计；脉冲由 TON 定时器 `T#1S` 产生）

## 5. 故障排查

| 症状（deploy_result.json 的 FAIL 行 / 现象） | 原因 | 处理 |
|---|---|---|
| `未找到 CODESYS.exe` | 未安装或非默认路径 | 安装见 §1.1，或 `set CODESYS_EXE=...` |
| `add device FAIL: device type not installed` | 安装时未勾 Control Win V3 | 重新运行安装包补装该组件 |
| `import PLCopen XML FAIL` | XML 结构问题 | 先跑 `python src\pipeline\validate_xml.py` 看问题清单 |
| `create online application FAIL` | 软 PLC 未启动 | 托盘启动 Win V3（§2.1），重跑部署 |
| `login / start FAIL`（提示网关未配置） | 工程未做一次性播种 | 按 **§2.3 第 2 步**配置通信网关并保存工程，重跑部署 |
| `login / start FAIL`（其它） | demo 2 小时到期 / runtime 停止 | 托盘或服务重启 runtime，重跑部署 |
| UaExpert 连不上 4840 | runtime 未运行 / 防火墙 | 同上；`telnet localhost 4840` 验证端口 |
| UaExpert 里看不到 `cnt` | 符号配置未发布变量 | 按 **§2.3 第 3 步**添加/勾选符号配置 → 保存 → 重跑部署 |
| 部署行为怪异、想完全重来 | 工程/状态残留 | 删除 `workspace\counter.project` 与 `deploy_result.json` 后重跑 |
| 脚本无输出、无 result.json | profile / 脚本组件异常 | IDE 里 Tools → Scripting → 试执行；确认安装含 Scripting 组件 |

> 报错定位技巧：`deploy_result.json` 的 `errors` 数组含完整异常栈，是从 CODESYS 内部带出来的第一手信息；
> 这也是将来回喂 agent 自动纠错的输入格式。

## 6. 已知限制与设计约定

### 6.1 工程模板机制（换工程免重复播种）

播种好的工程（含网关 + 符号配置）复制为 `src/codesys/template.project` 后，
编排器遇到不存在的目标工程会**自动从模板复制**再替换程序：

```bash
python src\pipeline\run_deploy.py --xml 新程序.xml --project workspace\新工程名.project
```

网关与符号配置随模板带过去，新工程零 GUI。同工程内换 XML 更简单：符号配置勾了
「总是更新变量」，新变量在每次 build 时自动纳入 OPC UA 发布，直接重新部署即可。

- **Demo 授权每 2 小时停**：长仿真前先重启 runtime 并重跑部署（闭环里每轮本来就重新下载，影响有限）
- **POU 名固定 `PLC_PRG`**：依赖 CODESYS 设备模板的任务默认调用该名字，导入即被调度；
  agent 生成契约中主程序 POU 必须叫 `PLC_PRG`
- **XML 只带 POU 逻辑**：设备、任务配置、符号配置由部署脚本负责装配
  （规避 PLCopen XML 对 task configuration 导入不完整的已知问题）
- **import_xml 签名随 SP 变化**：脚本已按 1/2/3 参数形态逐一尝试；若你的版本全部失败，
  请把 `errors` 里的异常信息反馈到仓库 issue
