# XML → CODESYS 部署手册

适用分支：`lx` ｜ 交付内容：把 PLCopen XML（IEC 61131-10）自动部署到 CODESYS 软 PLC 运行，
并用 UaExpert 通过 OPC UA 观察「每秒自增 1」的计数器变量。

---

## 0. 链路总览

```
src/plc/counter.xml ──► run_deploy.py ──► CODESYS.exe --noUI --runscript
                                              │
                                   deploy_project.py（CODESYS 内部）
                                   ①建/开工程 ②加设备 ③导入XML替换PLC_PRG
                                   ④符号配置(OPC UA发布) ⑤编译 ⑥下载+运行
                                              │
                              workspace/deploy_result.json（步骤成败+错误）
                                              │
                        CODESYS Control Win V3 ── OPC UA ──► UaExpert 观察 cnt
```

## 1. 软件安装（一次性，约 30 分钟）

### 1.1 CODESYS Development System + 软 PLC

1. 到 https://www.codesys.com 注册免费账号（需邮箱验证）
2. 登录后进入 **CODESYS Store**，下载 **CODESYS Development System V3.5**（选最新 SP，64 位安装包，如 "CODESYS 3.5 SP19 Setup (x64)"）
3. 运行安装程序，组件勾选：
   - ✅ **CODESYS Development System**（含 Scripting 组件，默认勾选）
   - ✅ **CODESYS Control Win V3 x64**（本机软 PLC —— 必勾）
4. 默认安装到 `C:\Program Files\CODESYS 3.5.SP19.0\CODESYS\CODESYS.exe`，
   编排器会自动扫描该位置；装到别处请设置环境变量：
   `set CODESYS_EXE=C:\<你的路径>\CODESYS.exe`

### 1.2 Python

本机已装 3.12 ✅（流水线只用标准库；`pip install -r requirements.txt` 装 pytest 即可跑单测）。

### 1.3 UaExpert（OPC UA 客户端）

到 https://www.unified-automation.com/products/development-tools/uaexpert.html
免费注册下载安装。

## 2. 一次性环境准备

1. **启动软 PLC**：开始菜单运行 `CODESYS Control Win V3 SysTray`（或 Win V3 x64），
   系统托盘出现图标即运行中。
   - 首次启动弹出的 **Demo 模式**提示选接受：无许可证时全部功能可用，
     **每 2 小时自动停一次**，从托盘重新 Start 即可（属正常现象）。
2. **防火墙**：首次启动 Windows 会询问放行，勾选专用+公用网络；
   或手动放行 TCP **1217**（CODESYS 网关）与 **4840**（OPC UA）。
3. 自检：CODESYS IDE → Tools → Connect to device…，能在列表里看到本地 runtime 即就绪。

### 2.3 一次性工程播种：网关 + 符号配置（约 2 分钟，仅此一次）

SP22 的无头脚本接口无法自动完成这两件事（`online.gateways` 在 `--noUI` 下为空、
符号配置的 `create_symbol_config` 调用被拒绝），但它们都**保存在工程文件里**——
在 IDE 里设置一次，之后所有自动部署永久复用：

1. 打开 CODESYS IDE → 文件 → 打开工程 → `D:\Study\SIMENS PLC\workspace\counter.project`
2. **配置通信网关**：双击设备树中的 `CODESYS Control Win V3` 设备 → 进入「通信设置」：
   - 网关下拉框 → 选择本机网关（名称形如 `CODESYS Gateway 3.5.22.30 <本机IP>`）；
     没有就点「添加网关」→ 主机名填 `localhost`
   - 设备：点「扫描」选中正在运行的 runtime（带绿点），或设备名填 `CODESYS Control Win V3`
   - 通信指示灯变绿即成功
3. **添加符号配置（OPC UA 发布变量）**：
   右键 `Application` → 添加对象 → **符号配置** → 双击打开它 → 点 **「准备...」** →
   勾选全部变量（至少 `PLC_PRG.cnt`）→ 建议同时勾选「**总是更新变量**」（之后 agent
   换新程序时新变量自动纳入发布）→ 确定
4. 文件 → 保存工程

> 注意：之后运行自动部署时，请**不要**同时在 IDE 中打开该工程（工程文件锁冲突）。

## 3. 运行部署

```bash
python src\pipeline\run_deploy.py
```

期望输出（每步 PASS，最后 `RESULT: OK`）：

```
[orchestrator] 启动无头 CODESYS 部署
[PASS] create project
[PASS] add device
[PASS] locate application
[PASS] drop template PLC_PRG
[PASS] import PLCopen XML
[PASS] create symbol configuration
[PASS] compile (generate_sourcecode)
[PASS] login / download
[PASS] start PLC
[orchestrator] 部署成功，PLC 已在运行。
```

说明：
- 首次运行约 1~2 分钟（无头启动 IDE + 编译 + 下载）
- 脚本**幂等**：重复运行会先删除旧 `PLC_PRG` 再导入，可反复部署新版本
- 换别的 XML 部署：`python src\pipeline\run_deploy.py --xml path\to\other.xml`（POU 名须为 `PLC_PRG`）

## 4. UaExpert 验证（看到每秒 +1）

1. 打开 UaExpert → 左上 **"+"** → Server URL 填 `opc.tcp://localhost:4840`
2. Security Settings 保持 **None** → **OK** → 双击新连接
3. 首次连接弹出证书信任对话框 → **Trust/Accept** 服务器证书
4. 左侧 **Address Space** 逐层展开：`Objects → <PLC 设备名> → Application → PLC_PRG`
   （不同 SP 版本节点层级略有差异，可直接在过滤框输入 `cnt` 搜索）
5. 把 **`cnt`** 拖入右侧 **Data View**
6. 观察数值：**每秒 +1** 即链路全部打通 🎉
   （`cnt` 为 DINT，从 0 起计；脉冲由 TON 定时器 `T#1S` 产生）

## 5. 故障排查

| 症状（deploy_result.json 的 FAIL 行 / 现象） | 原因 | 处理 |
|---|---|---|
| `未找到 CODESYS.exe` | 未安装或非默认路径 | 安装见 §1.1，或 `set CODESYS_EXE=...` |
| `add device FAIL: device type not installed` | 安装时未勾 Control Win V3 | 重新运行安装包补装该组件 |
| `import PLCopen XML FAIL` | XML 结构问题 | 先跑 `python src\pipeline\validate_xml.py` 看问题清单 |
| `create online application FAIL` | 软 PLC 未启动 | 托盘启动 Win V3（§2.1），重跑部署 |
| `login / start FAIL`（提示网关未配置） | 工程未做一次性播种 | 按 **§2.3 第 2 步**配置通信网关并保存工程，重跑部署 |
| `login / start FAIL`（其它） | demo 2 小时到期 / runtime 停止 | 托盘或服务重启 runtime，重跑部署 |
| UaExpert 连不上 4840 | runtime 未运行 / 防火墙 | 同上；`telnet localhost 4840` 验证端口 |
| UaExpert 里看不到 `cnt` | 符号配置未发布变量 | 按 **§2.3 第 3 步**添加/勾选符号配置 → 保存 → 重跑部署 |
| 部署行为怪异、想完全重来 | 工程/状态残留 | 删除 `workspace\counter.project` 与 `deploy_result.json` 后重跑 |
| 脚本无输出、无 result.json | profile / 脚本组件异常 | IDE 里 Tools → Scripting → 试执行；确认安装含 Scripting 组件 |

> 报错定位技巧：`deploy_result.json` 的 `errors` 数组含完整异常栈，是从 CODESYS 内部带出来的第一手信息；
> 这也是将来回喂 agent 自动纠错的输入格式。

## 6. 已知限制与设计约定

- **Demo 授权每 2 小时停**：长仿真前先重启 runtime 并重跑部署（闭环里每轮本来就重新下载，影响有限）
- **POU 名固定 `PLC_PRG`**：依赖 CODESYS 设备模板的任务默认调用该名字，导入即被调度；
  agent 生成契约中主程序 POU 必须叫 `PLC_PRG`
- **XML 只带 POU 逻辑**：设备、任务配置、符号配置由部署脚本负责装配
  （规避 PLCopen XML 对 task configuration 导入不完整的已知问题）
- **import_xml 签名随 SP 变化**：脚本已按 1/2/3 参数形态逐一尝试；若你的版本全部失败，
  请把 `errors` 里的异常信息反馈到仓库 issue

## 7. 与 agent 闭环的对接点（下一步）

| 接口 | 形态 |
|---|---|
| 部署 | `run_deploy.py --xml <path>`，退出码 0/1 |
| 结果回喂 | `workspace/deploy_result.json` → `errors[]` 直接进 agent 的纠错 prompt |

| 迭代 | 改 XML → 重跑部署 → 仿真指标 → 回喂（全流程无人工点击） |
