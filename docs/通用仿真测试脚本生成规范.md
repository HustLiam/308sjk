# 通用仿真测试脚本生成与干涉预检 v1

2026-11-03 后续方案调整：新任务默认固定校验配置，Agent 只提供模型与参数 JSON，固定程序检查模型结构及 OpenPLC 双向 IO，不做额外功能测试。实现、参数边界及真实联调未完成项见[模型生成与固定 IO 校验规范](模型生成与固定IO校验规范.md)。下文仅保留旧配置的实现及此前范围记录。

本规范适用于新设备场景，独立于机器人型号、轴数和组件类型。实现入口为 `SceneGenerationAgent.draft_collision_free_tests`；固定判据在 `test_safety.py`、`mechanics.py` 和 `simulation_tests.py`。模型独立测试不构成 PLC 在线验收或实机安全认证。

## 0. 当前检验范围（2026-11-03）

当前主要检验以下五部分。统一的是证据、测试操作和判定方法；设备相关的对象、运动关系、IO 与功能目标由 AML 提供。不能把六轴的测试动作直接套给其他设备，也不能由 Agent 自己定义“通过”。

| 部分 | 检查对象与方法 | 通过依据 |
|---|---|---|
| 1. 用途与验收要求 | 核对设备用途、组件/接口/运动副、IO、验证对象、初态、适用工况、容差和允许简化项；每条要求关联测试 ID | 要求可解释、对象存在且有对应检查器；缺少要求或检查器明确列为待补充/未覆盖 |
| 2. 静态与装配 | 先解析和构建，再检查实际装配模型的父子关系、接口对齐、运动副类型/轴向/锚点/自由度、单位/坐标、限位/初态及碰撞代理 | 实际模型与声明一致，初态不存在禁止的干涉，必要的运动体具有碰撞几何 |
| 3. 组件独立测试 | 在隔离装配中逐个激励执行器、传感器和 IO；核对声明与路由，再测试合法指令、实测反馈、编码/阈值及其他通道的非预期响应 | 写入作用于声明的属性/执行器，反馈来自实际状态；绑定正确与驱动响应正常分别给结论 |
| 4. 机构运动学 | 在合法、无碰撞且足以区分错误的姿态下检查固定连接、转动/移动副、耦合、接口相对变换与末端运动；全行程可达性另列 | MuJoCo 实测位姿与 AML 独立推导的机械关系符合容差；不能用到达限位代替连接关系检查 |
| 5. 整机工况 | 根据设备声明选择正常运行、启停/复位、联锁、组合动作和物料流等适用工况；装配后规划整段路径，隔离试跑，检查实际状态变化 | 已声明的功能目标与状态转换满足要求，适用工况覆盖完整；单组件或单轴全部通过不代表整机功能已覆盖 |

第 3 项 IO 仍检查声明/路由、指令实际作用、实际状态反馈三层，详见[六轴 IO 绑定规范](六轴IO绑定校验规范.md)。测试器直接读写仿真模型接口；不连接 PLC、不运行 PLC 程序，也不把 PLC 未验收作为当前模型检验的失败项。报告保留 `plc_acceptance: not_run`。

数值与参考数据部分仅保留基础健康检查：状态有限、无求解器异常，以及上述机械/IO 判定必需的基本容差。当前不增加高精度动力学标定、实机轨迹拟合或计量精度验收；这些未执行的项目不能被报告为已验证。已有 AML 明确要求的容差仍有效，不能为通过测试临时放宽。

### 判定与动作生成边界

- 机械关系、行程覆盖、驱动响应和工况合法性分别判定。超限指令、规划路径碰撞、前置状态不满足属于测试工况问题；不能仅凭这些证据认定机械连接错误。反向轴、错误父子连接等独立证据仍应报机械关系错误。
- Agent 获取实际隔离装配模型的碰撞几何后生成动作。整段路径先通过预检，再执行；运行中出现禁止干涉立即拦截并返回证据，重新规划，不能把穿透过程发布为有效测试回放。若初态本身干涉，先修正模型。
- 机械关系检查采用合法局部运动即可建立对应证据；显式要求的全行程仍必须单列覆盖。当前 `mechanical_joint` 程序还要求两端行程，不能通过改标签或缩小范围声称满足全行程。拆分独立的局部关系脚本与行程脚本属于后续计划格式扩展。
- 直接设置关节位置并计算正运动学，只能形成运动学证据。执行器跟踪、使能/停止和反馈响应必须通过驱动接口与实际仿真步检查。
- 未声明的任务不能由 Agent 猜测后自动验收；没有对应检查器、缺少可辨识激励或缺少覆盖的项目，记录为未覆盖/无法判定，不能自动标记通过或不适用。

### 与现有实现的对应和限制

`device_ir.py` / `simulation_contract.py` 解析要求与引用；`validation.py` 检查组件、装配及已有分拣整机夹具；`simulation_tests.py` 执行机械、安装、耦合和 IO 模块；`test_safety.py` 使用实际装配几何预检程序。机械模块的 `mechanical_relationship_status`、`full_travel_status`、`scenario_status` 独立输出，运动学模块的 `response_status` 为 `not_assessed`，驱动响应另看 IO 模块。

这五项是当前检验范围，不是宣称已经实现任意设备的五项全覆盖。当前分拣整机工况有固定夹具；其他设备通过 AML 所列机械/IO 模块，证明的是该声明范围。现有 `behavior_checks_complete` / `aml_scoped_tests` 不等同于任意设备完整工艺周期通过。新的整机功能、组合工况和未支持的组件行为仍需相应要求及固定检查器，不能只把现有模块换成五个分组就宣称完成。

## 1. 生成顺序

AML/DeviceIR → 候选组件构建检查 → 隔离整机装配 `test_planning_scene/` → 读取实际 MuJoCo 碰撞几何 → Agent 编排动作 → 固定检查器预检与独立动态试跑 → 不通过时反馈证据重写 → 保存通过预检的脚本 → 候选场景构建后再次检查实际模型 → 人工确认与冻结。

脚本生成必须发生在隔离整机装配之后。不能只凭组件声明、外形尺寸或单轴限位判断动作无干涉。几何初态已经干涉，或运动体缺少碰撞代理时，停止脚本生成并保留模型问题，不能靠删除测试或关闭碰撞过关。

## 2. Agent 输入与输出

Agent 接收实际编译的碰撞体、归属、初始包围盒、被检查的几何对、机械父子关系、运动副限位、耦合、原始测试目标；可编程机器人 IO 同时接收固定通道规则。包围盒只辅助规划，固定宿主使用实际编译几何核对。

输出为完整 `joint_paths` 与 `io_scripts`。每条机械路径含3～40个路点，每个路点声明全部标量关节位置（hinge为rad，slide为m）。允许多个运动副协同让位，必须考虑整段连续插值，保留目标副的两端行程覆盖，结尾全部回到初始状态；不得修改组件事实、几何、限位、豁免、容差和判据。不能通过只测安全子集冒称全行程通过。

输出外层只能包含 `joint_paths`、`io_scripts`；机械条目只能包含 `test_id`、`waypoints`，IO 条目只能包含 `test_id`、`steps`，不得使用 `cases`。每个输入目标 ID 必须恰好出现一次；对应输入列表为空时才允许返回空数组。结构错误先返回具体 JSON 路径、缺失/多余字段、重复/未知/遗漏的测试 ID，再校验每条程序的操作及覆盖。错误响应不自动改字段、不用基线补齐，不送入仿真。

机器人 IO 继续使用固定 drive/reject/observe/control/contact 契约。其他已实现 IO 内核仍由固定行为探针测试，不把未知行为伪装成 Agent 已实现的程序。不能验证的对象保持未覆盖，不能声称安全或完成。

## 3. 固定干涉检查

`DeviceCollisionProbe` 对所有实际编译设备组件生效，不以 `robot_control`、Robot6R 或指定关节名称判断是否启用。检查相对运动部件与其他部件/地面；静态焊接刚体、直接 AML 运动副/安装邻居以及同一组件内部直接相连的刚体按固定规则豁免。非相邻内部运动体仍被检查。地面干涉审计不随旧的求解器排除策略关闭；纯视觉几何不冒充碰撞代理。

工件与机器的正常输送、推料接触由现有物料行为探针验证，不纳入此处的机器部件穿透判据。该范围明确记录在报告；本检查不证明所有工件碰撞工艺正确。新的工艺接触规则需要设备事实及独立检查器支持，Agent 不能自增接触豁免。

机械路径在发布回放前按最多0.5°/1mm的步长对整段配置采样，实际运动再按声明的速度/加速度连续记录。IO 和施力探针的每个物理步也检查部件干涉；不合法的试探步回退状态且不生成该步回放。拒绝、取消均不留下规划用临时位置。此处为离散采样检查，不宣称连续碰撞检测或通用最优路径规划。

## 4. 纠错和失败边界

每轮保存原始请求、回复、模型几何上下文、脚本校验错误及干涉证据；证据包含部件对、路点/插值位置及穿透量。反馈给 Agent 后重新提交完整程序，最多3轮。三轮仍不合法则停止，不换基线、不跳模块、不降低标准。模型的绑定/连接错误仍由原固定判据独立报错，不能被路径拒绝掩盖。

`test_safety.json` 绑定 DeviceIR/模型/脚本/检查器版本，保存检查范围、问题与脚本来源。前端仅展示与当前模型、脚本和检查器匹配的报告；可审查多轴动作、下载预检报告、选跑及回放。局部选跑不替代全量结果。

## 5. 当前实证

2026-10-29，人工构造并通过 AML 解析的两种新设备：二维移动机构，以及升降＋旋转机构。几何规则明确由测试夹具提供，测试脚本由真实 DeepSeek 生成。两例首轮都因 tool/obstacle 干涉被固定检查器拒绝；Agent 根据实际碰撞证据在第二轮增加让位步骤，分别完成2项全行程检查。最终共5,634帧无部件干涉，所有原始失败证据保留。另有非机器人推料 IO 的步间干涉拦截测试。证据在 `E:/chagpt/2026-10-29-generic-test-safety`。

## 6. 导入与冻结的进一步设计评估

用户提出“冻结前隔离构建，装配后测试，测试通过再导入”。此顺序合理：隔离装配已足以提供实际碰撞几何，不需要预先冻结。导入应晋级已通过测试的同一份模型与资产，同时核对 AML/DeviceIR、MJCF、资产、IO映射、脚本和检查器摘要；全部机械/IO/功能要求通过、覆盖完整后才允许进入可执行场景。

当前实现已具备装配后规划和候选模型重检，但候选构建及正式冻结仍有重新构建路径。现有路径会对重建结果再次测试，不能直接沿用旧通过结论；若采用“同产物晋级”，需进一步将导入、人工审批及冻结锁定到已验证的不可变模型包。该晋级流程属于待评估变更，本次没有把候选自动审批或冻结，也没有宣称已实现这一完整导入语义。
