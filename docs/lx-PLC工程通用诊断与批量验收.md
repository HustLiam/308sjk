## 通用处理

失败诊断的输入包含当前 ST、需求规格、测试计划、失败判据，以及所有采集信号的首值、末值和变化次数。`diagnostic_context.json` 保存实际提供的证据。超过输入限长时明确标记程序是否被截断。

在线行为失败即使命中知识库，也要结合工程证据调用诊断模型。知识库建议是待验证假设，不能因为日志含某个数字或通用超时描述就阻止进一步分析。诊断输出包含问题类别、依据、修复建议和必须保持的行为；这些建议不改变确定性验收结果。

`program_review.py` 对 ST 的 CASE 选择变量、赋值顺序和后续 IF 做词法检查，指出同一扫描中可能被覆盖的状态转移，并给出行号。检查不依赖设备名、图形、状态变量名或状态编号。输送带、泵、气缸的不同变量及状态编号有独立回归用例。它不是完整 IEC 61131 解释器，分支可达性仍须结合源码和运行证据判断，因此结果只参与诊断，不据此直接改源码或判定失败。

所有设备的生成提示都要求检查：状态退出是否可达、同扫描写入的优先级、目标更新前计算的到位条件是否过期、定时器的调用和复位、全部收尾完成后才报告完成。修复仍由模型输出完整 XML，程序不拼装任务控制逻辑。

`event_delay.from/to.occurrence` 可选择 `first` 或 `last`，省略时保持首次真实边沿的旧含义。最后一次关闭、释放或收尾事件可以显式表达，不再依赖中文描述猜测。初始电平始终不等同于边沿。既有规格不会被静默改成最后一次事件。

数值条件支持 `{signal,op,value}` 的 `< / <= / > / >=` 比较，或 `{signal,equals,tolerance}`。BOOL继续使用相等比较。设备声明了到位误差的真实反馈，不允许以无容差精确相等代表到位；需求理解阶段会返回具体校验错误，要求模型保持原工艺并重新表达。容差必须为有限正数且不得超过该轴poswin。压力、位置、温度等阈值条件使用相同判定函数，验收和最佳版本比较不会采用不同计算规则。

本次初始基线执行了两个三角形任务；它们均完成真实路线，但模型选用反馈精确等于行程上限的验收前提，反馈最高为9而条件要求10，最终交付因缺覆盖被拒绝。其余18项未启动并明确标为未运行，没有报告整组成功率。上述条件表达修订完成后重新建立v2实验，全部20项重新生成，不把两个基线任务混入新版本成功率。

v2在第一个任务结束后通过 `STOP_AFTER_CURRENT` 停止，未运行后续19项。该任务第二个候选完成10/10项在线检查；独立几何查询却把启动前静止接触点也计作描边，造成错误拒绝。修订查询后对原trace的离线核验偏差为0.9734，4项请求检查均通过；原始结果保持不变，离线复判不计入新任务成功率。v3采用真实启动边沿后的任务窗口，只把接触时有平面位移的样本用于线段偏差检查，完整采样和接触状态核验仍保留全程。增加正反例，确认静止接触不误判为线段，而启动后的接触移动到请求之外仍会失败。

## 派生状态的40ms响应约束

用户明确确认：传感器反馈到PLC派生状态允许最多40ms响应。新增字段由需求理解模型生成，示例为：

```json
{
  "type": "forbidden_state",
  "when": {"signal": "pressure", "op": ">", "value": 5},
  "forbid": {"signal": "pressurized", "equals": false},
  "purpose": "derived_state_consistency",
  "response_s": 0.04,
  "response_source": "pressure"
}
```

计时从传感器源条件变化开始，不从每次错误输出重新计时。源条件已稳定很久后出现的20ms错误仍然失败。初始观测只有一次初始化响应预算；观测结束时仍未恢复一致，即使不足40ms也失败。时间依据实际采样时间戳，而不是简单删除两个样本。持续时长和响应时长均保留，全部原始不一致样本也保留。

校验要求响应源是when/forbid中的传感器输入，另一侧包含PLC BOOL状态输出；触发命令、HMI按钮和测试计划写入的输入不能冒充传感器源。`purpose=safety` 或省略purpose时仍是零时延检查，不能设置非零派生状态预算。用途仍属于需求规格的语义，模型必须遵守原始安全要求；形式校验不等于对任意设备完成安全证明。

采集顺序调整为先读状态线圈、后读数值反馈，避免把旧数值反馈和新状态组合成表面上的提前响应。Modbus读操作仍不是原子快照；时间判定采用观测时刻，分辨率受采样周期影响，不能宣称获得了传感器真实变化时刻的无限精度。

旧零时延v3中第一个三角形5个候选后未收敛，第二个任务首个候选通过，显示单次读取恰好一致不能证明通信时差消失。基础40ms版本首个任务首个候选通过后停止。上述任务全部只作诊断记录，不与最终固定版本的20项统计混合。

原有最佳版本保留规则继续生效：候选可能退化，被保留的修复基底不能用已通过行为的损失换取另一个指标改善。配置、规格和验收定义的问题不能通过修改 PLC 或放宽容差掩盖。

## 统计口径

每个 `solve` 保存 `iteration_metrics.json`。一轮指生成或修复一个候选并执行后续检查；静态校验内可能调用模型多次，因此同时报告候选轮数和实际 API 调用数，不能混为一谈。

每轮记录耗时、模型调用数和模型耗时，以及验收通过数、总数、实际执行数和未执行项。编译失败时验收实际执行数为0。条件前提从未发生而没有违规的检查，分别记录逻辑通过数与实际观察到的通过数，不能当作该行为已经得到验证。每次模型调用另存 `.timing.json`；不记录请求头或密钥。

任务总耗时从新任务启动起计算，包含需求理解、计划、全部候选、真实编译、物理验收和诊断。需求或规划失败的任务也保留，并进入总成功率分母。

### 中间事件与任务终态

恢复批次执行3项后暂停：两个尺寸六边形成功；七边形3个候选未成功。其测试计划的completion同时要求首次落笔信号为真和最终完成信号为真，违背最终抬笔要求。原因在旧提示与校验规则：强制将全部 `event_delay.to` 信号放入完成条件，把中间阶段的事件误当成结束时仍应保持的状态。此问题与图形边数无关，同样会影响先夹紧后松开、先建压后卸压等工艺。

修订后，所有中间事件仍按原验收规格在完整trace中判断；completion只表达真正的终态，不能仅凭测试计划自己写入的控制输入宣称完成。增加可选的 `path_checks[].terminal`：明确标为true的路径，最后一个路点还必须在最终采样时满足位置和工艺状态；中途检查点可标为false或省略，到达后允许继续执行。新生成的运动计划必须至少声明一条terminal路径，旧计划不被静默补标或改写。

生成PLC前，将completion与所有明确声明的最终路点转换为BOOL/数值区间，拒绝同一信号的相反状态、不相交位置范围，以及必然同时满足某条禁止条件的终态。证据不足的区间不判成必然冲突，继续由真实执行验收。冲突反馈给测试计划模型修复，不让PLC生成器改变设备行为来满足错误计划。算法使用信号引用、值域和比较操作，不依赖绘图仪、落笔名称、图形或固定状态编号；压力等独立信号有离线回归。

本次发现也说明：保持最佳版本的规则无法让错误测试计划变得正确。七边形的后续候选虽然实际完成了收尾，却失去错误completion要求的执行通过项，被拒绝替换旧版。解决办法是生成PLC前排除计划矛盾，修改计划后建立新任务与新实验；不能修改同一实验的判据，再把结果称为程序的单调改善。

修订版实验另存 `workspace/benchmark_general_terminal_20261020/`，全部20个任务重新生成。旧固定批次、3项恢复测试及其余11项未运行状态均保留，不混入新版本成功率。旧高推理配置多次先耗尽32768输出额度，再在重试时降低推理强度；新批次直接采用 `reasoning_effort=low`，额度仍为32768，完整XML与验收要求不变。此配置差异写入protocol，不据两个批次的差异单独推断某一修订的因果效果。继续批次时同时检查源码、模型、地址和生成配置，任一改变均须新建实验。

## 终态数值的反馈绑定

2026-10-21的长方形任务暴露了一项通用解释错误：模型分别用三个region_containment表示三个轴的终点，却以asset选择单轴并给另外两个分量填0；旧判定器实际按全部反馈检查每一个三维数组，导致已经到达正确终点的程序仍失败。原批次及其失败不改写为成功。

新增显式signals，与region_center逐项对应。例如位置可写signals=["joint_position_fb"]、region_center=[50]；压力可写signals=["pressure_fb"]、region_center=[7]。数值使用对应反馈的工程量，不固定为米；asset名称不承担选择分量的作用。多个反馈的顺序按signals声明，不按名称、地址或图形猜测。仅允许引用已声明的input INT数值反馈，拒绝缺失、重复、输出或BOOL引用。

需求阶段检查所有显式终态区域与设备量程是否有共同INT值；没有共同值时，返回需求模型修正规格，不进入测试计划和PLC生成。规划前再次检查；completion、明确标记的最终路点和终态区域必须相容。运行时按同一显式绑定检查真实反馈；缺少任一分量即失败。区域解释器的源码也纳入最佳版本比较，修改判定方法后不得沿用旧条件宣称程序改善。

新生成的区域条件必须带signals。旧的全局三维格式保留原有反馈次序，导入旧任务时不静默改变判断；单轴asset而无signals的含糊写法会被拒绝，要求明确引用。Schema、需求提示词、需求校验、计划预检和运行判定同步修改。压力、输送带位置和气缸行程等信号有独立离线用例，不据此宣称这些设备已完成物理测试。

隔离检出和合入主工作区后均为453项本地回归通过，1项原生编译排除。对原长方形失败规格的只读检查，已在PLC生成前检出三个含糊区域；新增模型调用0、部署0。正式批次结束前保持旧版本，合入后独立在线复验，结果不混入原批次成功率。
