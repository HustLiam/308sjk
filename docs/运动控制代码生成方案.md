# 运动控制代码生成方案（轴对象模板）

> **适用范围**：仅运动控制场景。非运动场景（分拣/液位/交通灯等）不走此方案，保持原有生成模式。
> **链路归属**：链路 A（MuJoCo 进程内）+ 链路 B-real（IgH EtherCAT + 真实驱动器）。
> 链路 B-sim（OpenPLC + Modbus）仅用于软件级 CI 门禁。

---

## 1. 轴对象（Axis Object）概念

```
一个"轴对象" = 轴内核 + MC 命令块组 + 轴参数（分层） + IO 绑定
                │        │            │                │
                │        │            │                └─ 五通道：cmd/sp/rel_d（入）+ fb（入）+ sw/v/err_id（出）
                │        │            └─ limits（行程/限幅）+ defaults（缺省动力学）+ poswin（到位窗口，跨侧契约）
                │        └─ 挂在内核上的命令接口：MoveAbsolute/MoveRelative/Home/Halt/MoveJog/ReadStatus…
                └─ 每轴唯一的运动发生器：INTERP 实例 + 目标/动力学总线（PLC_PRG 层实例化）
```

**分层语义（v4.0 现状，勿混淆）**：INTERP **不是** MC 块的内部实现，而是每轴唯一的**共享内核**——一个轴同时可能收到 Absolute/Relative/Home/Halt 多种命令，但只能有一条轨迹，故运动发生器每轴一份、被多个命令块共享。MC 块是命令适配器：校验（ErrorID）→ 触发沿锁存动力学到总线 → 置触发线；PLC_PRG 把各命令块的触发线 OR 后喂 INTERP。这套"总线 + OR 触发线"就是 PLCopen **AXIS_REF** 的手工模拟（无 REF_TO，见 §2.3 偏差 2；将来若封装 AXIS_CORE FB 即真引用，**当前未实施，仅演进方向**）。

**参数分层（v4.0 起）**：速度/加速度/减速度是**命令级参数**（MC 块每次调用携带，PLCopen 语义），轴对象提供**缺省值 + 限幅保护**：

```json
{
  "axes": [
    { "name": "x", "travel": [0, 800], "unit": "mm",
      "limits":   { "vmax": 200, "accel": 500 },
      "defaults": { "velocity": 200, "acceleration": 500, "deceleration": 500 },
      "poswin": 2,
      "io": { "fb": "%QW0", "rel_d": "%QW3", "sp": "%QW10",
              "sw": "%QW6", "v": "%QW13", "err_id": "%QW16" } },
    { "name": "z", "travel": [0, 300], "unit": "mm",
      "limits":   { "vmax": 100, "accel": 300 },
      "defaults": { "velocity": 100, "acceleration": 300, "deceleration": 300 },
      "poswin": 1,
      "io": { "fb": "%QW2", "rel_d": "%QW5", "sp": "%QW12",
              "sw": "%QW8", "v": "%QW15", "err_id": "%QW18" } }
  ]
}
```

- `travel`：行程范围（越程拒绝的依据，MC 块 ErrorID=1）；
- `limits`：物理限幅（INTERP 执行上限保护）；`defaults`：MC 调用未显式传动力学时取值；
- `poswin`：到位窗口——**PLC 插补层与 csk 判定引擎共用的唯一容差源**（csk 判据语义提案：定位类 done = |fb−target| ≤ poswin，poswin 统一提取），两側不得各定各的容差；
- `io`：五通道地址绑定（输入 fb/rel_d/sp + 输出 sw/v/err_id；线圈类触发 cmd_go/cmd_rel 等为**应用级**共享指令，不属单轴）。

**分层边界**：轴对象只封装**单轴能力**；多轴协调工序（目标表序列器、连续跟踪、笔互锁等）属**场景/应用层**（PLC_PRG 定制区，见 gc plotter3axis 实战形态），生成器不得把工序逻辑塞进轴模板。

## 2. 生成模板结构

生成的 PLCopen XML 固定包含以下 POU：

| POU | 来源 | 说明 |
|---|---|---|
| `INTERP` | **标准库**（一份拷贝，不随场景变化） | 插补引擎：梯形规划，每扫描输出一个位置设定点；按命令动力学（vel/acc/dec）执行，支持受控中止 |
| `DRIVE402` | **标准库** | 驱动器模型：CiA 402 状态机 + 位置环（CSP 跟随） |
| `MC_*`（10 块） | **标准库**（PLCopen MC 对齐层，2026-09-09） | 应用指令 API：Power/Reset/Stop/Halt/MoveAbsolute/MoveRelative/MoveJog/Home/ReadStatus/ReadActualPosition |
| `PLC_PRG` | **按场景生成** | 应用逻辑 + 轴实例化 + IO 接线 |

### 2.1 INTERP（标准库，所有场景共用）

```st
FUNCTION_BLOCK INTERP
  VAR_INPUT
    fire : BOOL;          (* 启动新插补（上升沿） *)
    pos_target : INT;     (* 目标位置 *)
    hold_req : BOOL;      (* 受控暂停（MC_Halt：减速保持） *)
    vel_req : REAL;       (* 命令速度（MC 块动力学参数锁存到总线） *)
    acc_req : REAL;       (* 命令加速度 *)
    dec_req : REAL;       (* 命令减速度 *)
  END_VAR
  VAR_OUTPUT
    Setpoint : INT;       (* 插补点（周期位置设定值 → 驱动器） *)
    Busy : BOOL;
    Done : BOOL;
    Aborted : BOOL;       (* hold 减速到零速即中止（供 MC 层置 CommandAborted） *)
  END_VAR
  VAR
    edge_ir : BOOL;       (* 边沿检测 *)
    pos, vel, tgt : REAL;
    dist, stop_d : REAL;
    SCAN_T : REAL := 0.02;
    POSWIN : REAL := 2.0;   (* ← 按轴对象参数覆写 *)
  END_VAR
  (* 梯形轨迹规划体… *)
END_FUNCTION_BLOCK
```

### 2.2 PLC_PRG（按场景生成，核心变化区）

v4.0 接线形态（每轴一组，命令块经总线驱动共享 INTERP；下图以 X 轴为例，Z 轴同构）：

```st
PROGRAM PLC_PRG
  VAR
    (* ── 轴内核实例 ── *)
    ix_x : INTERP;          (* 每轴唯一的插补内核 *)
    dv_x : DRIVE402;        (* 驱动器模型 *)

    (* ── MC 命令块组（挂在此轴上）── *)
    go_x  : MC_MOVEABSOLUTE;
    rel_x : MC_MOVERELATIVE;
    hm_x  : MC_HOME;
    hlt_x : MC_HALT;
    jg_x  : MC_MOVEJOG;
    rds_x : MC_READSTATUS;
    rap_x : MC_READACTUALPOSITION;

    (* ── 总线（= 手工 AXIS_REF：命令块 → 内核）── *)
    x_tgt      : INT;       (* 目标总线（默认 {axis}_sp，rel 触发时改写） *)
    x_vel_bus  : REAL := 40.0;   (* 动力学总线：命令触发沿锁存 *)
    x_acc_bus  : REAL := 80.0;
    x_dec_bus  : REAL := 80.0;
    go_x_exe   : BOOL;      (* 触发线（OR 后喂 INTERP.fire） *)
    rel_x_exe  : BOOL;
    hm_x_exe   : BOOL;

    (* ── IO 绑定（%QW 地址来自轴对象定义的五通道）── *)
    x_fb     AT %QW0  : INT;   (* 编码器反馈 ← 仿真/驱动器 *)
    x_rel_d  AT %QW3  : INT;   (* 相对距离 ← 主站 *)
    x_sp     AT %QW10 : INT;   (* 目标位置 ← 主站 *)
    x_sw     AT %QW6  : WORD;  (* 状态字 → 主站 *)
    x_v      AT %QW13 : INT;   (* 速度指令 → 主站（诊断） *)
    x_err_id AT %QW16 : INT;   (* MC ErrorID → 主站 *)

    (* ── 应用级共享指令/状态（不属单轴）── *)
    run       AT %QX0.0 : BOOL;
    cmd_go    AT %QX0.2 : BOOL;
    cmd_rel   AT %QX2.1 : BOOL;
    cmd_halt  AT %QX2.0 : BOOL;
    any_moving AT %QX1.2 : BOOL;
    prog_id   AT %QW20 : INT := 1;
  END_VAR

  (* ── 扫描头：采样驱动状态；目标总线取缺省 ── *)
  x_sw := dv_x.sw;
  x_tgt := x_sp;

  (* ── MC 命令层（校验 + 锁存动力学 + 置触发线）── *)
  go_x(fire := cmd_go, Position := x_sp,
       Velocity := 40.0, Acceleration := 80.0, Deceleration := 80.0,
       sw := x_sw, abort_bus := ix_x.Aborted,
       interp_exe := go_x_exe, dyn_vel := x_vel_bus,
       dyn_acc := x_acc_bus, dyn_dec := x_dec_bus);
  rel_x(fire := cmd_rel, Distance := x_rel_d, ActualPosition := rap_x.Position, ...);
  hm_x(fire := cmd_home, sw := x_sw, home_exe := hm_x_exe);
  hlt_x(fire := cmd_halt, ax_busy := ix_x.Busy);
  jg_x(JogForward := jog_fwd, ..., cur_pos := x_fb, jog_pos := x_jog_pos);
  rap_x(Enable := TRUE, ActualPosition := x_fb);

  (* ── 轴内核：触发线 OR 后驱动 ── *)
  ix_x(fire := go_x_exe OR hm_x_exe OR rel_x_exe, pos_target := x_tgt,
       hold_req := hlt_x.Stopping,
       vel_req := x_vel_bus, acc_req := x_acc_bus, dec_req := x_dec_bus);
  IF ix_x.Done OR ix_x.Aborted THEN
      go_x_exe := FALSE; hm_x_exe := FALSE; rel_x_exe := FALSE;
  END_IF;

  (* ── 插补点 → 驱动器（CSP：内核内直连，不经外部寄存器）── *)
  dv_x(cw := x_cw, Setpoint := ix_x.Setpoint, pos_fb := x_fb);

  (* ── 状态聚合经 ReadStatus；应用逻辑（工序/联锁）按场景定制 ── *)
  rds_x(Enable := TRUE, sw := x_sw, interp_busy := ix_x.Busy, v_act := x_v);
  any_moving := rds_x.Moving OR ...;
  ...
END_PROGRAM
```

### 2.3 PLCopen Motion Control 对齐层（MC_* 标准库，2026-09-09 v4.0）

MC 块命名与语义对齐 PLCopen MC Part 1 单轴子集，作为应用层的固定 API（**生成器只调不改实现**）。完整签名与状态输出组：

| MC 块 | 输入（要点） | 输出 |
|---|---|---|
| `MC_Power` | Enable, EnablePositive/Negative（CiA402 不分方向，仅门控） | Status, Busy, Error |
| `MC_Reset` | fire | Done, Busy, Error |
| `MC_Stop` | fire（电平）, v_act | Done, Busy, Error |
| `MC_Halt` | fire, ax_busy | Stopping, Done, Busy, Error（受控减速停不失能） |
| `MC_MoveAbsolute` | fire, Position, Velocity/Acceleration/Deceleration, sw, abort_bus | Done, Busy, Active, CommandAborted, Error, ErrorID |
| `MC_MoveRelative` | fire, Distance, ActualPosition, 动力学, sw, abort_bus | 同上（绝对目标 = 触发时实际位置 + Distance） |
| `MC_MoveJog` | JogForward/Backward, Velocity, cur_pos, sw | Busy, Error（起跳锚定实际位置） |
| `MC_Home` | fire, sw | Done, Busy, Error |
| `MC_ReadStatus` | Enable, sw, interp_busy, v_act | Valid, Moving, StandStill, Disabled, ErrorStop |
| `MC_ReadActualPosition` | Enable, ActualPosition | Valid, Position |

**ErrorID 枚举**（经 io_list `{axis}_err_id` 诊断出口可读）：0=无 ｜ 1=目标越程 ｜ 2=轴故障 ｜ 3=轴未使能。

**对齐映射与偏差**（生成器须知）：
1. `fire` = 标准的 `Execute`（matiec 保留字，见 §3.3）；`pos_target` = `Position`（INTERP 侧）；
2. **无 AXIS_REF**：轴绑定采用每轴一组 MC 实例（接线即绑定），标准轴引用抽象待真机移植时评估；
3. BufferMode（运动序列缓冲）首版不做；MC_Halt 中止当前命令记 CommandAborted，重发命令即恢复；
4. 动力学参数为 REAL、仅程序内部传递（io_list 仍 {BOOL,INT,WORD} 定点，契约②不变）；MC 块在触发沿把动力学锁存到 `{axis}_vel/acc/dec_bus` 总线供 INTERP 消费；
5. 中止信号（`INTERP.Aborted`）在 MC 块内做**上升沿检测**——上一命令的锁存中止不得误杀新命令（2026-09-09 实测坑）。

**接线约定**（PLC_PRG 生成模板）：目标总线 `{axis}_tgt` 每扫描默认取 `{axis}_sp`，MC_MoveRelative 触发时改写；状态聚合经 MC_ReadStatus（`any_moving`/`fault_any` 路由其 Moving/ErrorStop）。

## 3. 生成规则

### 3.1 变量命名规则

| 类别 | 格式 | 示例 |
|---|---|---|
| 轴内核实例 | `ix_{axis}` / `dv_{axis}` | `ix_x`, `dv_z` |
| MC 命令块实例 | `go_/rel_/hm_/hlt_/jg_{axis}`；`rds_/rap_{axis}` | `go_x`, `rel_z`, `rds_x` |
| 触发线（命令→内核） | `{go/rel/hm}_{axis}_exe` | `go_x_exe` |
| 目标总线 | `{axis}_tgt` | `x_tgt` |
| 动力学总线 | `{axis}_vel/acc/dec_bus` | `x_vel_bus` |
| IO 五通道 | `{axis}_fb/rel_d/sp/sw/v/err_id AT %QW{n}` | `x_fb AT %QW0` |
| 目标寄存器 | `{axis}_sp AT %QW{n}`（= 目标总线缺省源） | `x_sp AT %QW10` |
| 应用级指令 | `cmd_go/cmd_rel/cmd_halt/cmd_home` 等（共享，不属单轴） | `cmd_go AT %QX0.2` |
| 状态输出 | `move_done`, `any_moving`, `all_oe`, `fault_any` | 固定名 |

### 3.2 IO 地址分配规则

```
%QW0~9:    编码器反馈（输入，仿真/驱动器写入）+ 相对距离 rel_{axis}_d（%QW3~5）
%QW10~19:  位置指令（输出，PLC → 驱动器 CSP 设定点流）+ ErrorID 诊断 {axis}_err_id（%QW16~18）
%QW12+n:   目标寄存器（输入，主站写入最终目标）
%QW20:     prog_id（固定）
%QX0.x:    应用指令（主站写入）
%QX1.x:    应用状态输出
%QX2.x:    MC 扩展指令（cmd_halt 2.0 / cmd_rel 2.1，2026-09-09）
```

### 3.3 matiec 限制遵守清单

| 限制 | 对策 |
|---|---|
| `Execute`/`Target`/`Hold`/`DT`/`STEP` 是保留字 | 用 `fire`/`pos_target`/`hold_req`/`SCAN_T`/`pstep` |
| **标识符大小写不敏感**：`busy` 与 `Busy` 同名冲突（2026-09-09 实测） | 同一 POU 内输入输出避免仅大小写差异；必要时 `ax_busy`/`busy_rs` 后缀 |
| INT 不能 AND/OR 位运算 | 控制字/状态字用 WORD |
| FB 内禁 CONSTANT 块 | 参数用带初值的普通 VAR |
| BOOL→INT 需显式转换 | BOOL_TO_INT() |
| 不同 FB 的边沿检测变量必须不同名 | `edge_ir`, `edge_rs`, `edge_ma`, `edge_rl`, `edge_hl`, `edge_jg`, `edge_ab` 等（按 FB 名后缀） |

## 4. 应用逻辑模板

### 4.1 基本运动（goto 模式，v4.0）

```st
(* v4.0：主站/应用只须 写 {axis}_sp 目标寄存器 → 发 cmd_go 脉冲。
   MC 层自理校验/动力学/触发，INTERP 出插补点，DRIVE402 跟随——
   应用层不再直接操纵 fire 触发线。 *)
(* 外部时序约定：目标寄存器先于 cmd_go 上升沿建立（≥1 扫描周期） *)
```

多步工序（目标表序列器）用连续跟踪模式：触发线保持到 Done，目标变化自动启动新轨迹（gc plotter3axis 实测形态，见 changelog 路线 v2.0 行）。

### 4.2 带安全互锁的运动

```st
(* Z 轴不在安全高度时禁止 X/Y 运动（龙门/机械手典型联锁）
   v4.0：封锁应用级触发，不动 MC/内核内部状态 *)
z_safe := (z_fb <= z_safe_limit);
IF NOT z_safe THEN
    cmd_go_x_gated := FALSE;   (* 场景级门控：仅当 z_safe 才放行 X 的 go 触发 *)
END_IF;
```

### 4.3 回零

```st
(* v4.0：主站置 {axis}_sp=0（场景约定：回零目标走目标寄存器）→ 发 cmd_home 脉冲；
   MC_Home 置 home_exe → 并入 INTERP 触发 OR → 梯形回零。
   已知偏差（§2.3-4）：MC_Home 未加 Position 输入，目标仍走场景约定。 *)
```

## 6. 轴对象映射绑定规范（AML → PLC 代码 / 仿真模型，2026-09-09）

> 目标：轴参数**单一事实源**——只在 AML 定义一次，②a（PLC 展开）与 ②b（场景生成）都消费 ⓪ 的确定性产物 `device_model.axis_objects`，一致性检查器对账三方。LLM 只做工艺层（序列/互锁/目标值），**永不生成或改写轴参数**。

### 6.1 axis_objects 字段规范（device_model v1.1 提案，gc 拥有，RFC 中）

`device_model.kinematics.axes[]` 现有字段（axis/device/type/stroke/unit/vmax/accel/poswin/wrap）保留，升级点：

```json
{
  "axis": "x_axis", "device": "Motion3AxisStation/gantry/x_axis",
  "type": "linear",                      // linear | rotary_modulo | rotary_finite
  "stroke": [0, 100], "unit": "%",
  "wrap": 0,                             // rotary_modulo 环形回绕周期；linear 为 0
  "limits":   { "vmax": 40.0, "accel": 80.0 },        // ← 原 vmax/accel 迁移（物理限幅，INTERP 保护上限）
  "defaults": { "velocity": 40.0, "acceleration": 80.0, "deceleration": 80.0 },  // MC 调用缺省动力学
  "poswin": 2.0,                         // 到位窗口：PLC INTERP 与判定引擎共用容差源（唯一来源）
  "io": {                                // 通道绑定（role → io_points 变量名，⓪ 按命名规则推断）
    "fb":     "x_fb",     // 必需：编码器反馈
    "sp":     "x_sp",     // 必需：目标位置
    "sw":     "x_sw",     // 必需：状态字
    "v":      "x_v",      // 必需：速度指令
    "rel_d":  "x_rel_d",  // 可选：相对距离入口（v4.0）
    "err_id": "x_err_id"  // 可选：ErrorID 诊断出口（v4.0）
  }
}
```

**role 推断规则（⓪ 确定性执行，非 LLM）**：对每根轴 `A`（设备名去 `_axis` 后缀得短名 `a`），在 io_points 中按名匹配 `{a}_fb / {a}_sp / {a}_sw / {a}_v / {a}_rel_d / {a}_err_id`；必需通道缺失 → 记 problems（不猜）；可选通道缺失 → 省略该 role（MC_MOVERELATIVE/err_id 诊断不展开）。地址沿用 io_points 的 `%QW` 声明（R6 已对账），本规范不新增地址。

### 6.2 三方消费方式

| 消费方 | 用法 | 权威依据 |
|---|---|---|
| ②a PLC 生成（gc） | 每根 axis_object 按 §2.2 模板展开 MC 实例组+INTERP+DRIVE402+总线：travel→MC 越程拒绝界限、defaults→MC 调用动力学、limits→INTERP 执行上限、poswin→INTERP POSWIN、wrap→INTERP WRAP、io→定位变量接线与命名（§3.1） | 本文 §2/§3 |

### 6.3 等价验收（契约测试）

motion3axis 基准：AML 提取的 axis_objects 经确定性模板展开的 XML **与现行已验收 motion3axis v4.0 逐字段等价**（POU 结构/接口/参数/接线；等价即证明映射链无损——与 ⓪→① io_list 预填的逐字等价契约测试同法）。plotter3axis 同法补第二条基准。

### 6.4 落地顺序
