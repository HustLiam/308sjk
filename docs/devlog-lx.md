### 场景：双缸顺序控制（cylinder_seq，29/29 一次通过）

- CASE 步进链：A 伸→B 伸→B 缩→A 缩循环，步号暴露在 %QW0 便于断言；

### 场景：PID 液位连续调节（pid_tank，三轮 9/9）

**R1（XML 笔误）**：`<initialValue>` 嵌套的关闭标签误写成 `</simpleValue>`，xml2st 解析层拦截（mismatched tag line 34）。教训：嵌套标签笔误是手写/生成 XML 的高频错误；排查时 Read 工具显示有迷惑性，用 `repr()` / 标签栈脚本确认。部署失败时旧程序继续运行（读到的全 0 是旧程序的 IO 空间）——失败保护语义符合设计。

**R2（两个独立问题）**：
- 脚本竞态：Modbus 写完 AUTO 线圈立刻读 `dev_alarm`，未等 PLC 20ms 扫描周期，读到上一周期的 FALSE。修复：写后 `sleep(0.3)`。通用结论：外部客户端"写完立刻读"是唯一会踩扫描异步的写读对；
- 参数失配：Kp=35 在 e=50 时输出需求 1750 → 深度饱和 + 积分顶格，回路退化为 bang-bang；且对象 τ=50s 物理上 30s 只能到 45（`pv(t)=100(1-e^(-t/50))`，与实测逐点吻合——执行层无错，错在整定）。

**R3（重整定）**：
- 对象加快：模型系数 0.02→0.04（τ 50s→25s）；
- PI 按零点对消极点设计：Kp=5、Ki=0.2（Ki/Kp = 对象极点 0.04）；
- 抗饱和升级为**条件积分**：`IF NOT (mv_r>100 AND err>0) AND NOT (mv_r<0 AND err<0) THEN integ += ...`——饱和且误差同向时暂停积分，退出饱和后无超调；
- 结果：无超调收敛 |pv−50|≤4、阶跃 50→70 跟踪、全程 mv∈[0,100]。

**技术结论（可复用）**：
1. INT 定点对外 / REAL 内部计算的混合模式在链路 B 完全可行——内部 `err/integ/mv_r` 用 REAL 不受 %Q 契约限制，只有 IO 边界做 `INT_TO_REAL`/`REAL_TO_INT`；
2. matiec 实测正常的标准构造：`INT_TO_REAL`/`REAL_TO_INT`/`ABS(INT)`/比较运算/多行 IF 嵌套；
3. 验收脚本内嵌一阶被控对象做真闭环（pv 由 mv 积分产生）是验证连续控制场景的有效形态，脚本中打印 pv/mv 采样表相当于简易 trace，定位参数问题靠它。
