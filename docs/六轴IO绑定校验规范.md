# 六轴 IO 绑定校验规范 v1

本规范对应 `308sjk.robot_io_rules/1`，实现权威为 `src/agent/scene_agent/robot_io.py`。适用于当前六轴实例的 6 路角指令、6 路实测角反馈、6 路到位、使能/复位/就绪/故障和 3 路操作触点，共 25 路 IO。固定检查器裁定，Agent 生成受限数据脚本。此规范是项目测试方法，不声称标准认证或实机验收。

## 1. 验证对象与结论边界

验证对象是 AML IO 到组件属性、执行器及反馈量的绑定。正常激励采用初始姿态附近的局部有效窗口，不能用全行程扫动证明绑定。全行程、结构关系、工作空间、碰撞与负载测试单独保留。

| 证据 | 分类 | 结论 |
|---|---|---|
| 地址/方向/类型/写入者/比例不符，作用到错误组件或执行器，反馈编码/阈值错误 | `io_binding_error` | IO 绑定失败；不据此推断机械关系错误 |
| 指令对象和目标正确，但实际角未在超时内响应，或其他关节实际漂移超差 | `response_failed` | 响应未达标；绑定结论 `inconclusive`，继续定位物理/控制因素 |
| 正常激励超出局部窗口或未知指令/断言混入脚本 | `script` | 脚本无效，执行前拒绝并反馈给 Agent；不生成设备绑定失败结论 |
| 初始状态或合法小幅路径被碰撞/环境阻断 | `scenario_blocked` | 工况受阻；绑定结论未覆盖，不等于错绑或机械关系错误 |
| 非法边界值被拒绝，且模型时间和实际位置未前进 | 正向通过证据 | 说明拒绝行为正确，不能把预期拒绝记为设备失败 |

每个 IO 模块分别记录 `binding_status`、`response_status`、`scenario_status`，其 `mechanical_relationship_status` 一律为 `not_assessed`。绑定结论为 `passed`、`failed` 或 `inconclusive`；静态声明通过不能替代尚未完成的行为验证。未通过/未覆盖仍不能用于整机冻结。

## 2. 事实与局部激励窗口

事实仅来自 DeviceIR：稳定组件和运动副 ID、PLC 地址、方向、类型、写入者、物理量、换算比例、编码范围、初始角、物理行程、位置容差、响应超时。固定检查器直接读取实际编译的执行器关节引用、运行时端口、实际 q、IO 与驱动属性，不采用 Agent 给出的期望值。

局部诊断角窗口定义为：

`initial ± min(5°, 10% of joint travel)`，再与物理关节范围及 PLC 编码范围相交，量化成合法整数指令。此窗口是绑定测试方法，不修改关节限位，不声明经过安全认证。运行前按实际碰撞几何检查路径；无法覆盖所需正负激励时应阻断，不允许静默缩小到无法检错的幅值。

## 3. 固定规则

| 规则 ID | 判据 |
|---|---|
| `declaration` | IO 名称、类型、方向、地址、写入者、组件、quantity、换算与 io_map/运行时一致；错误类型、编码越界及非法写入者均被拒绝 |
| `routing` | `driven_joint_id`、控制器归属、实际执行器 transmission 关联到 AML 指定关节 |
| `command` | 单通道正、负激励及回初始值；目标属性等于原始值乘 AML 比例，实际角在容差/超时内响应 |
| `isolation` | 其他未声明关联通道的目标不变；实际关节漂移另记响应证据，不把物理反作用直接归为串线 |
| `feedback` | 对实际 q 注入不同合法状态，再由正常反馈内核读数；按 AML 比例取整及声明的编码饱和，不复制命令 |
| `in_position` | 根据实际角与指令角的误差判定；至少覆盖容差内和刚越过容差的状态 |
| `controller` | 禁能不就绪；使能且无故障就绪；急停原因存在时复位无效；原因消失但未复位继续锁存；有效复位后恢复；所属关节使能属性与控制器门控一致 |
| `contact` | 操作触点 false/true/false 通过拥有写权限的输入接口传递；不能测试者直接写仿真反馈 |
| `rejection` | PLC 编码下界−1、上界＋1 只作为拒绝用例；不作为运动目标 |
| `scenario` | 模型和脚本版本匹配；合法性与无干涉前提独立记录，不能转换成机械关系失败 |

角反馈状态注入只证明传感编码和阈值，不证明执行器驱动过程。指令测试必须通过正常运行时写指令并读取实际 MuJoCo 运动，不能直接设置 q 冒充响应。

## 4. Agent 输出契约

Agent 接收规则 JSON、每个通道的类型/编码/局部窗口、相关量和测试 ID，返回全部通道的程序。每个程序 3～20 个用例；不得输出判据、expected、容差、目标绑定、Python 代码或 verdict。

| 通道类别 | 允许的步骤 | 最低覆盖 |
|---|---|---|
| 指令角 | `drive(value)`、`reject(value)` | 超过两倍位置容差的正负激励，最后一个 drive 恢复初始值；上下两侧非法编码拒绝 |
| 实测角/到位 | `observe(position_rad, reference_value)` | 至少3个不同状态，初始角两侧、容差内（≤0.75倍）和刚超容差（1.25～2倍）；只在合法窗口内注入 |
| 控制器信号 | `control(enable, reset, estop_ok)` | 禁能、使能、原因存在不能复位、故障锁存、原因消失后复位 |
| 操作触点 | `contact(value)` | false/true/false |

Agent 自主选择合法幅值、参考值、顺序与重复次数。固定宿主检查器按通道规则自动执行声明/类型/权限检查，并解释动作程序、读取实测值和裁定。两者的职责分别记录；离线基线标记 `baseline`，真实模型生成标记 `agent`，禁止模型失败后改用基线并冒称生成成功。

模型回复缺通道、删负向覆盖、正常 drive 越界或夹带断言时，保存原回复和验证错误并反馈 Agent；最多3次，无效脚本不能执行。机械模板保持原样，不因 IO 脚本通过而改写碰撞或整机结论。

## 5. 产物与前端

`robot_io_rules.json` 保存此设备的规则、事实摘要和通道窗口；`simulation_tests.json` 保存 Agent 的实际程序及规则摘要。模型请求/原始回复/纠错记录在任务 `model_calls/simulation_tests/`。结果和回放沿用独立测试产物，绑定 DeviceIR、模型、规则、脚本和检查器摘要。

前端分别展示 IO 绑定通过数及工况受阻数，每个通道可查看实际脚本，显示“绑定错误”“响应未达标”“工况受阻”；机械工况不得合并为 IO 错绑。所选模块运行不覆盖全量报告，IO 通过不自动审批或冻结模型，不产生 PLC 在线验收结论。

## 6. 检错能力验证

必须验证：交换地址、错误比例、执行器接到另一关节、错误到位阈值、反馈复制指令可被检出。另构造几何碰撞与零增益驱动，分别得到工况受阻和响应未达标，而非 IO 错绑/机械关系错误。每次变更执行相关回归并保存真实六轴模型与 Agent 脚本联调证据。

## 7. 机械测试路径与 IO 结论的隔离

新设备生成现优先使用 [通用仿真测试脚本生成规范](通用仿真测试脚本生成规范.md) 中的装配后、多运动副路径生成与纠错。本节的局部回放方式继续用于已有基线脚本的诊断兼容，不替代新 Agent 的整条避让路径规划。

单关节目标位于角度限位内，不等于整机姿态或整条路径无干涉。机器人机械模块在回放前用独立状态预检原计划，结束或取消均恢复原实际位置；预检拒绝的姿态只保存在诊断证据中，不作为已执行运动或回放帧。

全行程路径被拒绝时，另对初始值附近 `±min(5°,10%行程)` 的局部路径预检；两侧激励必须超过两倍声明的角度容差。局部路径合法才执行连续运动学检查。结果分别记录局部 `mechanical_relationship_status` 与 `full_travel_status=not_covered`，总模块为 `blocked`、分类 `motion_plan_rejected`，界面显示“路径需重规划”；全行程覆盖要求不能因局部通过而删除或判为完成。局部也无法合法覆盖时不执行运动，连接关系结论为未覆盖。实际轴向/连接/位姿错误仍明确失败，不得被路径拒绝掩盖。此方法不实现多轴避障规划或完整工作空间验收。
